# Contributing

Thanks for helping. This crawler touches other people's servers, so the politeness
contract comes before everything else.

## Hard rules (a PR that breaks one is closed)

1. **No bot-detection evasion.** One User-Agent (`VoyagerBot/<ver> (+…/BOT.md)`), no
   header/UA/TLS-fingerprint rotation, no proxy pools, no stealth plugins, no CAPTCHA
   solving. A challenge, 401 or 403 means detect → park, never retry with another
   identity. `deny.toml` bans the known evasion crates.
2. **Every request to a crawl target needs a `ClaimPermit`** (minted only by
   `vc-frontier`; `clippy.toml` enforces it), a lease check and a global rate token.
3. **Honour every opt-out signal:** robots.txt (RFC 9309 + our stricter 401/403 rule),
   Crawl-delay, X-Robots-Tag, meta robots, TDM reservations, Content-Signal.
4. **Nothing on `policy/denylist.yaml` is ever fetched**, including brand domains.
5. **Raw first:** nothing derived from a capture is visible before the segment commits.
6. **Provenance and licence on everything;** `restricted` sources are not ingested.
7. **No secrets in the repo; logs never contain page content or tokens.**

## Workflow

- Branch from `main`. Agent branches are `agent/<task>[-slug]` and may only touch the
  paths their task owns ([docs/ownership.md](docs/ownership.md)); CI checks this.
- Write the failing test first, then the code.
- Before pushing:

  ```bash
  cargo fmt --all -- --check
  cargo clippy --workspace --all-targets -- -D warnings
  cargo test --workspace
  cargo deny check
  python3 -m pytest -q scripts/tests        # if you touched scripts/, sources/ or policy/
  ```

- Dependencies are added only to the root `[workspace.dependencies]` by a maintainer.
  Never run `cargo update` in a feature PR.
- Fill in the PR template's no-evasion checklist honestly.

## Adding a source

Only relevant and pertinent sites are added, and the owner approves every addition in the
PR. No non-travel sites.

1. Say which part of the Voyager app the source serves and why: the required
   `relevance: {sections: [...], why: "..."}` block. `sections` comes from a closed list
   (`flights weather hotels activities places walking_tours events visa sim tips
   emergency_card getting_around forex packing itinerary`); `why` is one plain sentence about
   the traveller-facing data it gives. A `news` or `blogs` source must read a travel section
   (the URL contains `travel`) or a whole-travel publication listed in
   `crates/vc-sources/src/relevance.rs`. Validation and CI reject a spec that breaks this.
2. Check the site's robots.txt for `VoyagerBot`/`*`, its terms, and the denylist.
3. Add `sources/<id>.yaml` (schema: `schemas/source.schema.json`). Pick `licence.class`
   and `source_class` per spec §5.9/§17.8; unknown terms → `restricted`, `enabled: false`.
   Sources from `docs/research/seeds.yaml` are generated by `scripts/seeds_to_sources.py`
   — change its tables (including `RELEVANCE`), not the output.
4. Regenerate the registry `docs/SOURCES.md` (and the wiki page) with
   `python3 scripts/sources_doc.py`; CI fails when it is out of date.
5. `python3 -m pytest -q scripts/tests` and `vcrawl admin source validate <id>`.

The source scout only files proposals (`vcrawl admin source list --proposed`); it never
approves or enables anything. A person decides with `vcrawl admin source approve <id>`, which
prints a draft spec for a PR.

## Reporting a site problem

If VoyagerBot misbehaves on your site, see [BOT.md](BOT.md) — the opt-out works
without waiting for us.
